# KiCad 原理图自检要点（2026-09-27，05_mcu_comm 第 3 轮总结）

## 1. 引脚名：隐藏用开关，绝不清空

- 想「不显示引脚名」时，改符号属性 `(pin_names (hide yes))`；**不要把 `(name …)` 改成空串**。
- 清空引脚名的三个后果（05 页第 2 轮踩过，第 3 轮撤销）：
  1. 网表 `<node pinfunction=…>` 丢失 → LED 的 `-`/`+`/`A`/`K`、晶振 `OSC1/OSC2` 极性语义没了，自动核对工具再也核不了极性；
  2. 图纸内嵌 `lib_symbols` 与 `hardware/lib/jlc/jlc.kicad_sym` 不一致，将来一次「与库同步」就把改动悄悄撤销；
  3. 违反「符号原样取自嘉立创」。
- 校验办法：脚本化比对嵌入符号与库（**只允许差 `jlc:` 库名前缀**），`re.sub(r'\s+',' ',块)` 归一化后逐字比较。
- 引脚名压在本体内是**符号库 quirk**，正确做法是挪字段位置规避，规避不掉的记进报告，**不改符号**；根治要去 `tools/fetch_jlc_parts.py` 归一化时统一加隐藏开关。

## 2. KiCad 文件格式陷阱

- **不写 `justify` 节点 = 居中对齐**（KiCad 总是显式写 `(justify left)` 表示左对齐）。
  用渲染实测验证过：JP1 位号锚点 365.76，PDF 里画在 363.91–367.36（中心 365.64）→ 确实居中。
  自检脚本解析 property 时若把「无 justify」当左对齐，会误报几毫米的差。
- 字段的**有效角度 = 存的角度 + 符号旋转角**（mod 360）。垂直器件的字段若不这么算，横向/纵向会判错。
- 内嵌 `lib_symbols` 里的符号名带库名前缀（`jlc:NAME`），库文件里是裸名——比对时要剥前缀。

## 3. 用 pymupdf 读渲染文字做自检的坑

- 同一段文字**可能被画两次**（去重按 `(bbox, text)`）；一个字段也可能被拆成**多个 span**（同一行、水平间隙 ≤1.6mm 的合并）。
- 1.27 字号的实际渲染高约 **2.03–2.09mm**，字符步进约 **1.23–1.33mm**——比「0.6×字高」这种估算宽得多，用估算宽度做重叠判定会漏报。
- 坐标换算：PDF 用户单位 → mm 用 `72/25.4`；A3 = 420×297mm。
- 单独导出子图（`kicad-cli sch export pdf 子图.kicad_sch`）正好出 1 页，适合做渲染复核。
  单图 ERC 会报一堆 `lib_symbol_issues` / `footprint_link_issues`（缺工程库配置），**ERC 要以根图为基准**。

## 4. 自检项设计（05 页第 2 轮的 6 项有洞，第 3 轮补上）

必须成对做的两类检查：

1. **几何：符号本体/字段/引脚名两两不相交，且要跨器件比**。
   只比「自己的字段 ↔ 自己的本体」抓不到「A 的字段压在 B 的本体上」——第 2 轮 R55 的位号被 JP1 本体压住就是这么漏掉的。
2. **渲染：字段的真实文字盒 ↔ 任何不属于本符号的渲染文字**（标签文字、说明文字、别人的引脚名）。
   器件外的标签文字既不是字段也不是本体，纯几何检查永远看不见它被压。
   豁免规则：本符号本体范围内的文字（库自带、画在本体内的引脚名/脚号）不算。

> 判据优先级（沿用）：KiCad ERC > 网表/PCB 焊盘网络 > 自写几何/渲染脚本。
> 新检查写完要做**负例验证**（拿上一轮产物跑一遍，确认它真能报出已知缺陷），否则可能是空跑。

## 引脚名重叠：在库里关，不在图里清（2026-09-27 05 页复核 P1-R3）
- 嘉立创符号没写 `pin_names`，KiCad 默认把引脚名画在本体内侧 → LED 的「+」、晶振 OSC1/GND 粘连压本体；挪字段管不到引脚名
- 清空嵌入符号的引脚名 = 与库不一致、网表丢极性语义、同步库即撤销（第 2 轮的错法）
- 正解：`tools/fetch_jlc_parts.py` 的 `hide_small_pin_labels()`：≤4 脚符号加 `(pin_names (hide yes))`，两脚且名为 1/2 的再加 `(pin_numbers (hide yes))`；取库后自动做、幂等，格式与 `kicad-cli sym upgrade` 一致（99 个符号）
- 改库后重跑各页生成器即可同步；04/05 页网表逐脚 0 差异

## 符号镜像 `(mirror y)`：三个实测结论（2026-09-27 02 页分段 A）

1. **世界坐标**：rot=0 时 `(mirror y)` 就是 `world_x = px − ix`、`world_y = py − iy`（只翻局部 x）。
   引脚方向的**世界向量**也要把 x 分量取反。网表实测验证过（`/tmp/mt`：R1 pin1 镜像后落到右边的桩）。
   rot=90/180/270 的公式见 `hardware/gen/check_02_layout.py::pin_world`。
2. **水平对齐会被一起翻转**：实例上写 `(justify left)`，镜像后渲染成**右对齐**。
   实测：02 页 U1 位号锚点 154.94，PDF 里画在 152.16–154.70（结束在锚点）。
   **镜像器件的字段一律用「居中」（不写 `justify` 节点）**——居中对镜像免疫，也正好对上 8a 的判据。
3. 镜像器件**不要**按符号库的左右直觉摆脚：MP2797 在库里的右侧脚（电芯）镜像后落到图纸左边。

## 位号必须「字母前缀 + 纯数字」

- `C219B` 这种尾随字母的位号，KiCad 的 annotator 解析不出序号，根图导网表会报
  `Warning: schematic has annotation errors, please use the schematic editor to fix them`。
- 定位手法（值得复用）：全工程搜 `?` 位号、搜跨页重号 → 都不是；**把可疑实例单独留在子图里再导一次**
  → 一个实例就能复现。02 页规格书原写 `C219B`，改成 `C226` 后警告消失。
- 检查脚本里加一条 `re.fullmatch(r"[A-Za-z]+[0-9]+", ref)` 兜住。

## 几何自检对符号变换**不敏感**，必须有网表逐脚核对

- 把 `pin_world` 的 mirror 分支屏蔽掉再跑检查 1–8，**依旧全 PASS**：
  它们比的全是「我自己算的几何 vs 我自己算的几何」，变换一错就两边一起错。
  那次副本的网表里 U1.1 已经接到 VCP 上（灾难性接错），几何检查一声不吭。
- 补法：以**根图**导网表，逐脚对规格书的预期网络（02 页 = `check_02_layout.py` 检查 9，
  U1 48 脚 + 外围件每个端子 + NC 脚必须真悬空 + DNP 标志 + 局部电源不许并到全局轨）。
- 负例验证的做法：检查脚本读环境变量 `AFE_HW` 换硬件目录 → 复制一棵硬件树、人为制造缺陷、
  跑一遍确认会报。**逐项记进报告**（哪些项做过负例、哪些是「本页不会触发的守卫」）。
- `kicad-cli sch export netlist` **默认出 S-表达式**，要 XML 必须加 `--format kicadxml`。
- ERC 以根图为准；子图单跑没事，但根图跑才能看到跨页标签对端。

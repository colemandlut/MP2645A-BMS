# KiCad 原理图自检要点（2026-09-27，05_mcu_comm 第 3 轮总结）

## 1. 引脚名：隐藏用开关，绝不清空

- 想「不显示引脚名」时，改符号属性 `(pin_names (hide yes))`；**不要把 `(name …)` 改成空串**。
- 清空引脚名的三个后果（05 页第 2 轮踩过，第 3 轮撤销）：
  1. 网表 `<node pinfunction=…>` 丢失 → LED 的 `-`/`+`/`A`/`K`、晶振 `OSC1/OSC2` 极性语义没了，自动核对工具再也核不了极性；
  2. 图纸内嵌 `lib_symbols` 与 `hardware/lib/jlc/jlc.kicad_sym` 不一致，将来一次「与库同步」就把改动悄悄撤销；
  3. 违反「符号原样取自嘉立创」。
- 校验办法：脚本化比对嵌入符号与库（**只允许差 `jlc:` 库名前缀**），`re.sub(r'\s+',' ',块)` 归一化后逐字比较。
- 引脚名压在本体内是**符号库 quirk**，正确做法是挪字段位置规避，规避不掉的记进报告，**不改符号**；根治要去 `tools/fetch_jlc_parts.py` 归一化时统一加隐藏开关。

## 2. KiCad 文件格式陷阱

- **不写 `justify` 节点 = 居中对齐**（KiCad 总是显式写 `(justify left)` 表示左对齐）。
  用渲染实测验证过：JP1 位号锚点 365.76，PDF 里画在 363.91–367.36（中心 365.64）→ 确实居中。
  自检脚本解析 property 时若把「无 justify」当左对齐，会误报几毫米的差。
- 字段的**有效角度 = 存的角度 + 符号旋转角**（mod 360）。垂直器件的字段若不这么算，横向/纵向会判错。
- 内嵌 `lib_symbols` 里的符号名带库名前缀（`jlc:NAME`），库文件里是裸名——比对时要剥前缀。

## 3. 用 pymupdf 读渲染文字做自检的坑

- 同一段文字**可能被画两次**（去重按 `(bbox, text)`）；一个字段也可能被拆成**多个 span**（同一行、水平间隙 ≤1.6mm 的合并）。
- 1.27 字号的实际渲染高约 **2.03–2.09mm**，字符步进约 **1.23–1.33mm**——比「0.6×字高」这种估算宽得多，用估算宽度做重叠判定会漏报。
- 坐标换算：PDF 用户单位 → mm 用 `72/25.4`；A3 = 420×297mm。
- 单独导出子图（`kicad-cli sch export pdf 子图.kicad_sch`）正好出 1 页，适合做渲染复核。
  单图 ERC 会报一堆 `lib_symbol_issues` / `footprint_link_issues`（缺工程库配置），**ERC 要以根图为基准**。

## 4. 自检项设计（05 页第 2 轮的 6 项有洞，第 3 轮补上）

必须成对做的两类检查：

1. **几何：符号本体/字段/引脚名两两不相交，且要跨器件比**。
   只比「自己的字段 ↔ 自己的本体」抓不到「A 的字段压在 B 的本体上」——第 2 轮 R55 的位号被 JP1 本体压住就是这么漏掉的。
2. **渲染：字段的真实文字盒 ↔ 任何不属于本符号的渲染文字**（标签文字、说明文字、别人的引脚名）。
   器件外的标签文字既不是字段也不是本体，纯几何检查永远看不见它被压。
   豁免规则：本符号本体范围内的文字（库自带、画在本体内的引脚名/脚号）不算。

> 判据优先级（沿用）：KiCad ERC > 网表/PCB 焊盘网络 > 自写几何/渲染脚本。
> 新检查写完要做**负例验证**（拿上一轮产物跑一遍，确认它真能报出已知缺陷），否则可能是空跑。

## 引脚名重叠：在库里关，不在图里清（2026-09-27 05 页复核 P1-R3）
- 嘉立创符号没写 `pin_names`，KiCad 默认把引脚名画在本体内侧 → LED 的「+」、晶振 OSC1/GND 粘连压本体；挪字段管不到引脚名
- 清空嵌入符号的引脚名 = 与库不一致、网表丢极性语义、同步库即撤销（第 2 轮的错法）
- 正解：`tools/fetch_jlc_parts.py` 的 `hide_small_pin_labels()`：≤4 脚符号加 `(pin_names (hide yes))`，两脚且名为 1/2 的再加 `(pin_numbers (hide yes))`；取库后自动做、幂等，格式与 `kicad-cli sym upgrade` 一致（99 个符号）
- 改库后重跑各页生成器即可同步；04/05 页网表逐脚 0 差异

## 符号镜像 `(mirror y)`：三个实测结论（2026-09-27 02 页分段 A）

1. **世界坐标**：rot=0 时 `(mirror y)` 就是 `world_x = px − ix`、`world_y = py − iy`（只翻局部 x）。
   引脚方向的**世界向量**也要把 x 分量取反。网表实测验证过（`/tmp/mt`：R1 pin1 镜像后落到右边的桩）。
   rot=90/180/270 的公式见 `hardware/gen/check_02_layout.py::pin_world`。
2. **水平对齐会被一起翻转**：实例上写 `(justify left)`，镜像后渲染成**右对齐**。
   实测：02 页 U1 位号锚点 154.94，PDF 里画在 152.16–154.70（结束在锚点）。
   **镜像器件的字段一律用「居中」（不写 `justify` 节点）**——居中对镜像免疫，也正好对上 8a 的判据。
3. 镜像器件**不要**按符号库的左右直觉摆脚：MP2797 在库里的右侧脚（电芯）镜像后落到图纸左边。

## 位号必须「字母前缀 + 纯数字」

- `C219B` 这种尾随字母的位号，KiCad 的 annotator 解析不出序号，根图导网表会报
  `Warning: schematic has annotation errors, please use the schematic editor to fix them`。
- 定位手法（值得复用）：全工程搜 `?` 位号、搜跨页重号 → 都不是；**把可疑实例单独留在子图里再导一次**
  → 一个实例就能复现。02 页规格书原写 `C219B`，改成 `C226` 后警告消失。
- 检查脚本里加一条 `re.fullmatch(r"[A-Za-z]+[0-9]+", ref)` 兜住。

## 几何自检对符号变换**不敏感**，必须有网表逐脚核对

- 把 `pin_world` 的 mirror 分支屏蔽掉再跑检查 1–8，**依旧全 PASS**：
  它们比的全是「我自己算的几何 vs 我自己算的几何」，变换一错就两边一起错。
  那次副本的网表里 U1.1 已经接到 VCP 上（灾难性接错），几何检查一声不吭。
- 补法：以**根图**导网表，逐脚对规格书的预期网络（02 页 = `check_02_layout.py` 检查 9，
  U1 48 脚 + 外围件每个端子 + NC 脚必须真悬空 + DNP 标志 + 局部电源不许并到全局轨）。
- 负例验证的做法：检查脚本读环境变量 `AFE_HW` 换硬件目录 → 复制一棵硬件树、人为制造缺陷、
  跑一遍确认会报。**逐项记进报告**（哪些项做过负例、哪些是「本页不会触发的守卫」）。
- 造负例时**先确认篡改本身没把文件改坏**：2026-09-27 02 页分段 C 改 `.kicad_sch` 里的文字时
  漏了一个引号，结果网表为空，9a/9c **各报 48/52 条**，看起来像「改一处炸全页」。
  判据：负例只该让**目标那一条**报警；其它检查项一起炸 = 大概率是篡改把文件弄坏了，先修篡改。
- `kicad-cli sch export netlist` **默认出 S-表达式**，要 XML 必须加 `--format kicadxml`。
- ERC 以根图为准；子图单跑没事，但根图跑才能看到跨页标签对端。

## 文字重叠检查：合并 span 会让它**失明**（2026-09-27 02 页分段 C，最重要的一条）

- 判据链：`rendered_runs()` 的合并规则是「同一行、水平间隙 ≤1.6mm 就并成一段」。
  **互相压着的两段文字水平间隙是负的**，必然 ≤1.6mm，于是必然被并成**一段**，
  于是「比 runs 两两相交」的重叠检查什么都看不见 —— 02 页有一处 x 方向压 7.9mm 的真缺陷，
  在页面上存在了两整段（A 段 + B 段）而自检全 PASS。
- 正解：新增 `rendered_spans()`（**去重但不合并**的原始 span），重叠判定用原始 span；
  合并后的 runs 只留给「认领字段」用。改完立刻报出 3 类 13 处此前被藏起来的真缺陷。
- 教训可以外推：**任何「先归一化再比较」的检查，都要问一句归一化会不会把待检的差异抹掉**。

## pymupdf 的 span bbox **不是墨迹**，重叠阈值必须按比例给（同段实测）

- bbox 含字体的上/下伸部：同一段文字块里相邻两行会互相穿 ——
  字号 2.4 的标题压字号 1.8 的正文穿 **0.948mm**；J5 位号字段（高 3.55）压说明文字穿 **0.929mm**。
- 真缺陷（§9 第 4 行压 `AFE_3V3` 标签）穿 **1.026mm** —— 和假重叠只差 0.078mm，
  **单靠「重叠多少 mm」的阈值分不开**。
- 可用判据：**纵向重叠 / 较矮 span 的高度**。实测真缺陷 **54%**、假重叠 ≤**39%**，取阈值 **45%**。
- 试过但**失败**的分档法：按「左端是否对齐（x0 相等）」分档 —— 同一行文字会被拆成多个 span
  （「§9 电源：…」首 span x0=210.68、次 span x0=216.85），左端并不相等，会误判。
- 结论：细粒度的墨迹判断，pymupdf 的字体度量给不了；要更准就得上像素。当前 45% 阈值够用，但要记进报告。

## A3 图框与标题栏的越框豁免（实测）

- 图框矩形实测 **x 10.0→410.0、y 10.0→287.0 mm**（A3 = 420×297）；
  旧代码写 `PAGE_MARGIN = 8.0` 是错的，会漏报 2mm 的越界。
- KiCad 自带标题栏的文字会画到 **x≈418.94**（本身就越出 410 边框），
  所以「文字越框」检查必须豁免标题栏区域 `(295.0, 250.0, 420.0, 297.0)`，否则自己告自己。

## 笔画字体宽度标定（用于落笔前先算行宽）

- `宽 = size × (0.9507×窄字数 + 1.3120×宽字数)`；宽字 = U+3000–303F / U+4E00–9FFF /
  U+FF00–FFEF / U+2E80–2EFF。实测 §9 第 1 行预估 69.34mm、实渲 67.45mm（**高估 2.8%**，方向安全）。
- 排版约束要写进生成器的注释里（「这一带每行 ≤89mm、往下 y≥54.7 是某列字段的地盘」），
  否则下一段接手的人会把文字又写回去。

## 墨迹盒模型与检查 10–13（2026-09-27 02 页第 2 轮，按 Opus 复核补漏）

第 1 轮的检查 1–7 量不出「标签压本体 / 标签叠标签 / 字段跑到别人器件上」，根因是**字宽模型太窄**：
旧 `text_width` 用 0.6×size/拉丁字、1.0×size/汉字，比本文件上面标定的 0.95/1.31 **低估约 50%**，
纵向 `text_bbox`（±size/2）也偏小。修正后的模型（`h` = 字号）：

- 墨迹高度 **1.50h**；拉丁 **0.92h/字**、汉字 **1.50h/字**；
- 锚点 → 墨迹盒：`top` = `[y−0.25h, y+1.25h]`、`bottom` 对称、居中 ≈ `y±0.75h`（系统偏差约 0.2mm）；
- **全局标签**的文字画在图形框内，模型盒整体偏左约 2mm → 额外水平外扩 `GLBL_PAD = 2.0`（宁多报不漏报）。

四条检查（阈值全部由「改前快照 vs 改后树」两棵树差分标定，实测数字记在
`design/02_afe-draw-report.md` §8.3）：

| 检查 | 判据 | 两个反直觉点 |
|---|---|---|
| 10 标签压本体 | 相交 `ox>0.15 且 oy>0.15` | 全局标签要 pad，否则漏报 |
| 11 标签叠标签 | 横向重叠 ≥ 较窄者 40% **且** 纵向间隙 <1.0 **且** 锚Δx ≥1.0 | **间隙分不开真假**：真缺陷间隙 +0.64（没压上），合法的 PACKP 同名对也是 +0.64；分开它们的是**锚点横向错开量**（真缺陷 Δx 6.35 重叠 91%，合法对 Δx 10.16 重叠 26%，同列紧排 Δx 0 → 放行） |
| 12 字段挂错器件 | `d_别人 < d_自己 − 0.5 且 d_自己 > 2.0`（2D 边到边） | 0.5mm 余量不能省：同排等距器件（C203/C204/C205）会出现 Δ=−0.00 的**完全平局**，不留余量满屏假报 |
| 13 说明文字互压 | 锚Δx ≥2.0 **且** 纵向间隙 <0.5 | 必须**排除同 x 的上下两行**（见下） |

**检查 11 只比「标签 vs 标签」**：全局标签的文字画在图形框内，模型与渲染的**纵向**偏差 0.2–1.2mm
（实例：GND @(360.68,88.90) 与 §6 说明首行，模型间隙 +0.24，PDF 实测 +0.86）。涉及说明文字的交给 13。

**几何上不可判的一类（要如实说）**：「2.4 号标题 + 紧接 1.8 号正文」是全页统一风格，
模型墨迹重叠 0.89mm（§9）、0.93mm（§10），渲染 span 重叠同为 0.93–0.95mm —— 与「标题压正文」
这类真缺陷同量级。所以 13 项按设计**豁免同 x 的两行**，标题与正文的间距只能靠人工/风格约束。

## 新检查先报出的不是 0 条：同类缺陷必须同修（同轮）

- 复核只点了 C213 的 GND 压本体，新检查同时报出 **C221 的 GND 几何逐字节相同**
  （Δ 都是 2.97 × 0.44）——「同病同修」，不要只修被点到的那一处。
- 另一条复核没点到的同类：**C219 的值**「100nF 100V」右端离 C226 极板只剩 0.41mm
  （模型：离自己本体 3.07、离 C226 0.41）。诊断手法值得复用：把**全部 106 个字段**的
  `d_自己 − d_别人` 排序，唯一显著为负的那条（−2.66，次名 −0.00）就是真缺陷。
- 两处都在**生成器**里修（C221 下端引线 2.54→3.81、C219 值改到本体左侧右对齐），
  **不要为了消警而放宽阈值** —— 放宽度量等于把检查改成空跑。

## 负例验证的落点：把「上一轮冻结快照」留在仓库里

- `review/02-r1/` 是第 1 轮的冻结快照，检查脚本读环境变量 `AFE_HW` 切硬件目录：
  `AFE_HW=review/02-r1 python3 hardware/gen/check_02_layout.py` → **FAIL 10 条**；
  `AFE_HW=hardware` → PASS。回归负例从此是**一条命令**，不依赖 /tmp 里的临时副本。
- 快照里没有根图 → 网表核对项自动 SKIP，这是设计如此（否则每次都误报）。
- 「本轮只改字段与版面、不改连接」的证明方式：改前先导出「位号.脚 → 网络」逐行排序存盘，
  改后再导一次 `diff`，要求 **0 差异**（02 页第 2 轮 325 行 0 差异）。

## ERC 的「几条」不属于本页：必须读 JSON 的 `sheets[]`（2026-09-28 03 页分段 B）

- `kicad-cli sch erc --format json` 打印的「Found 6 violations」是**整张根图**的汇总，
  光看这个数字**判断不了本页干净没干净**。逐条信息在 JSON 的 `sheets[]` 里：
  每张子图一个 `{path, uuid_path, violations[]}` 条目，**`path` 就是层级路径**（`/`、`/开关电容主动均衡/`…），
  每条 violation 的 `items[].description` 才带标签名/器件名（如 `Global Label 'DSG_G'`）与 `pos`。
- 03 页实例：6 条 `isolated_pin_label` **全在 `path: "/"`**（标签 `DSG_G`/`CHG_G`/`SRP`/`SRN`/`FET_MID`/`PACK+`，
  属 01/02 页），`path: "/开关电容主动均衡/"` 的 `violations` 是**空数组** → 「本页 0 条」有据可依。
- 想确认「某标签是不是本页的」别靠猜：`grep -o -E "\"(A|B)\"" 本页.kicad_sch`，空集就不是本页的。

## 「逐脚核对」必须按本页 refs 过滤（同轮，79 条假 FAIL 的根因）

- `kicad-cli sch export netlist` 导的是**整张根图的网表**。检查器若拿「网表里有什么网络」去对
  「本页应该有什么网络」，01/04/05 页的 `GND`/`+3V3` 之类全会变成「本页不存在」的 FAIL
  （03 页实测 **79 条**）。
- 正解：只遍历**本页 refs** 的脚（`refs_here = {本页所有位号}`），再对每个脚比网络名。
- 同类教训：**检查器的「期望值」必须只覆盖被测对象**，否则报出的条数与真实缺陷无关。

## 两脚件 R/C/F 允许脚号对调，检查器不能自造脚号（同轮，8 条假 FAIL）

- 规格书若写了「R/C/F 两脚对调都可以、二极管不可对调」，检查器的逐脚表就要照做豁免，
  判据：`got["1"]==want["2"] and got["2"]==want["1"]` 且 `ref` 前缀属 `R/C/F`；
  D/Q/U/J 仍严格逐脚（极性语义真的存在）。
- 否则会出现这样的假 FAIL：生成器把 R32k 的脚 1 接到物理左侧的 GP 轨（对的），
  检查器按自己拟的脚号判成「反」——**被检查的是检查器的臆测，不是图**。
- 报告里要如实写「R/C/F 两脚对调 N 处（规格书允许）：位号…」，别悄悄放行。

## 器件本体尺寸以**库读数**为准，字段落位不能凭直觉（同轮，8 条 FAIL 的坑）

- C30k（`CL05B104KO5NNNC`，竖放 rot 270）在世界坐标里是 **x±2.03 / y±2.54**——纵向比外观高。
  字段先摆到基线 `R−2.54` 时，8 条 `[6] …压在本体上` 立刻报出来；落到 `R−3.81`（离本体顶 0.635mm）
  才同时满足「字段不压本体」与 8a「字段认领渲染串」。
- 推论：**摆字段前用 `parse_pins`/本体盒算一遍可用间隙**，别按「大概 2mm」估。

## 两栏行距不同 ⇒ 跨栏「同高对齐」物理上不可能（同轮，版面偏差的正当理由）

- 03 页左右两栏行距不同（左栏 52.07、右栏错位 26.67），规格书建议「F30k 与 VBk 同高」
  **9 只不可能同时对齐**。采用等节距排布 + **两端都用标签**（`BALk` 全局标签 / `VBk` 局部标签），
  连接靠网表名而非导线 → **电气完全等价**，只是读图不直观。
- 这类「版面建议做不到」的偏差要**写进报告的偏差小节**（连理由与等价性一起），不要默默改。

## 「网络→脚集合」是「脚→网络」的独立方向，两者都要有（2026-09-28 03 页分段 C）

- 9c 只做「本页每个脚 → 应是哪个网络」；它对**期望表里漏写的脚**完全失明（表里没写的脚根本不被遍历）。
  补 **9j**：把期望表按**网络名**聚合，再拿网表里同名网络的**实际成员集合**去比（多一个件/少一个件都报）。
  负例：表里删掉 `Q301.3` → 9j 立刻报「网络 `X1` 成员不符：网表多出 ['Q301']」。
- **9j 的对调豁免要按「该器件的总脚数」判，不能按「它在这个网络里的脚数」**——
  每个网络里一个件只有一个脚，`len(w[ref]) == 2` 永远为假，8 只对调过的 R321–R328 全被误报。
  正解 `len(PART_EXPECT[ref]) == 2`。（**「用错粒度的集合做判据」是这类检查最常踩的坑**。）
- 两侧都做完，才能说「60 个网络逐一核对」而不是「274 个脚逐一核对」；两者在报告里要分开写。

## 网络类（netclass）能在网表上正面验证，别只靠读 pattern（同轮）

- 判据链：`mp2645a-bms.kicad_pro` 的 `net_settings.netclass_patterns` × **网表里的真实网络名**。
  通配符是 `*`/`?`（不是正则），要自己翻译：`?`→单字符、`*`→`.*`，再 `re.fullmatch`。
- 03 页实测：`BAL_3A ← ['BAL?', '/开关电容主动均衡/X?', '/开关电容主动均衡/VB?']`
  —— `X1–X8`/`VB0–VB8`/`BAL0–BAL8` 全命中，`BAL_CLK` **不**命中（`BAL?` 特意只用一个 `?`）。
  把 pattern 写成文件名 `/03_balancer/X?` → **8 条 `Xk` 全部落空**（网表路径用的是图纸名）。
- 所以「网络类对不对」有两个必须分开的失败模式：① 路径写成文件名（全不命中）；
  ② 通配符写宽成 `BAL*`（把时钟也卷进 3A）。检查器两条都要拦。
- 副作用：**改子图的 sheet name 会让 3A 网络类静默失效**，改完必须重跑这条检查。

## 同构检查（8 节同构）：不看期望表，只看网表自身（同轮，值得复用）

- 做法：把「第 k 节 11 件」的每个脚连同网络名做**角色归一化**（`VBk→VB#`、`VB(k−1)→VB@`、
  `INk/DRVk/GNk/GPk/Xk` 同理），再逐节比这张「归一化签名」——第 2–8 节必须完全相同，
  第 1 节允许**指定的**差异（03 页：只允许 `C32` 且必须是 `CLK_R`）。
- 附带两条同类检查：① 某个网络跨的**节号跨度** `max−min > 1` → 报（跨节只许相邻，如飞电容 `Xk–X(k+1)`）；
  ② **全局标签全集**必须恰好等于接口清单（03 页 = `BAL0–BAL8` + `BAL_CLK`）。
- 与「逐脚核对」互补：逐脚核对是「我照着规格书画的，画对了没」；同构是「8 节是不是一套画法」，
  不依赖规格书的期望表，能抓到**规格书本身写错**的情况（例如某节漏写一个件，期望表也一起漏）。
- **位号前缀的坑**：签名要按「前缀 + 去掉末位数字」分组（`R301→R30`、`R311→R31`），
  只按字母前缀分组会把 `R30/R31/R32` 混成一个键而互相覆盖，8 节于是「恒等」（检查空跑）。
- 负例：把第 6 节里一处 `VB5` 标签改成 `VB6` → 同时触发「第 5 节结构不同」与「`VB6` 跨第 [5,6,7] 节」。

## 字段角度：rot 180 用 `fa = 0`，不是 `(360 − rot) % 360`（2026-09-28 03 页第 2 轮 P2-4）

- **症状**：P-MOS（Q311–Q318，rot 180）的位号/值在 PDF 里**上下颠倒**（`span['dir'] == (-1.0, 0.0)`）。
- **根因**：`SCH_FIELD::GetDrawRotation()` **只在符号变换满足 `y1 != 0`（即 rot 90/270）时**
  才把水平/垂直互换；rot 180 时 `y1 == 0`，**直接用字段的存储角度**。旧公式给 180° → 正好倒过来。
  经验公式：rot 0/90/180/270 分别用 `fa = 0`（180 也写 0），"反向"要靠**图形本身**判断而不是公式。
- **附带**：rot 180 下 KiCad 会**取反水平对齐**，`justify left/right` 会左右互换；
  **`justify center` 对取反免疫**，是旋转件字段的安全选项。
- **验证方法**：`page.get_text('dict')` 里 `line['dir']` 是 `(1.0,0.0)`（正立）还是 `(-1.0,0.0)`（倒立），
  比看渲染图快且可断言 —— 03 页第 2 轮把它写进自检。

## 换符号（同封装不同厂家）也要走规则 00 ⓪：先比引脚坐标，再看图形定极性
## （2026-09-28 03 页第 2 轮：1N5819WS → BAT54WSL9，都是 SOD-323）

- 同封装**不代表**符号几何相同：先从 `jlc.kicad_sym` 读新符号的引脚坐标再决定要不要重画线。
  本轮实测 `BAT54WSL9` 与 `1N5819WS` 引脚**逐位相同**（`1`=(-5.08,0)、`2`=(5.08,0)），
  于是只改 `lib_id`/`value`/`LCSC` 三处，导线/junction 一个不动。
- **两个脚名都是 `passive` 的二极管，脚号没有极性含义**，K/A 只能读图形：
  | 符号 | 闭合三角顶点 | 三角底面 | 阴极竖杠/肖特基钩子 |
  |---|---|---|---|
  | 1N5819WS | x=-1.27（＝脚 1 侧） | x=+1.27 | -1.78..-0.76 |
  | BAT54WSL9 | x=-1.27 | x=+1.27 | -2.03..-1.02 |
  | SS210 | x=-1.27 | x=+1.27 | -2.03..-1.02 |
  → **顶点侧（x 小的一侧）＝阴极＝脚 1**，三家画法一致，可作通用判据。
- **检查设计（9q）**：脚号本身无意义，所以「图形」与「§3.2 网表」必须**一起**判：
  (a) 脚 1 坐标必须落在顶点侧、阴极杠/钩子也在同侧；(b) 网表 `D30k.1=DRVk/2=GNk`、`D31k.1=GPk/2=DRVk`。
  只做 (b) 会漏掉"库符号被换成人家的正负极画法"，只做 (a) 会漏掉"网络接反"。
- **值/LCSC 双表核对（9p）**：一张表比「图 ↔ §8.1c 决策」（库符号名 + 值 + LCSC），
  另一张比「图 ↔ `docs/02-BOM.csv`」；值比较要有**首 token 回退**（`1k 1%` vs BOM 的 `1k`），
  否则会假报。
- **负例**：R302 的实例 `lib_id` 换回旧符号 → 9p 报 1 条；D301 整体转 180° → 9q 报
  `K(脚1) 是 'GN1'、A(脚2) 是 'DRV1'`（同时 9c/9j/9o 一起报）。
  整库改名 `jlc:BAT54WSL9 → jlc:BAT54WS_T` 是**坏负例**：网表导出直接崩、级联 511 条，
  负例要挑**只影响一处**的注入点。
